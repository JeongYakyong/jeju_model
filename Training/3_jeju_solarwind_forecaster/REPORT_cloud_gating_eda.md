# 태양광 운량 게이팅 EDA (2026-09-27)

> **결론 한 줄: 일사 예보로 운량 입력을 게이팅하면 4~9월엔 편향을 절반 가까이 줄이지만
> 12~2월은 검증할 아카이브 자체가 없다(겨울 1회뿐). 적용 전, 검증만 완료.**
> 선행 문서 → `REPORT_solar_clearsky_underprediction.md`, `REPORT_cloud_feature_audit.md`.

## 배경

재훈련(Colab) 전에 "운량 입력 자체를 서빙 시점에 바로잡을 수 있는가"를 검증했다.
서버에서 최신 DB(`data/input_data_jeju.db`, 2026-09-28 까지)를 받아
`forecast_horizon`(예보) × `historical`(실측)을 D+1(12z, 전일 21시 발표) 낮시간(9~16시)
기준으로 조인해 분석했다. **서빙 코드는 건드리지 않았다 — 전부 오프라인 검증.**

## 기각한 가설

- **용량(capacity) 과소추정** — 등록용량(KPX, 2026-07 약 1268MW, 타 신재생 혼입)과
  실측 피크(455MW)의 격차를 의심했으나, `collect_historical.recompute_jeju_capacity`
  가 이미 **실측 발전량의 running cummax**를 쓰고 있었다(레거시 `Solar_Capacity_Est_jeju`
  는 이미 제거됨). 옛 모델 DB(`jeju_energy_nouse.db`)도 `Solar_Capacity_Est` 피크가
  실측 발전량 피크와 소수점까지 일치 — 옛 모델도 같은 cummax 방식이었다. **무혐의.**
- **출력제한(curtailment)** — 태양광이 거의 100% 우선순위 급전이라 사용자가 직접 기각.
  (2024-06 정책 변경은 train/val/test split 에 이미 반영돼 있음, 사용자 확인.)
- **옛 모델(`jeju_energy_nouse.db`, 2026-01~05)의 운량 예보 자체는 오히려 정확했다**
  (낮시간 전운량 P25: 관측 0.10 vs 예보 **0.025** — 관측보다 더 맑게 나올 정도).
  그런데도 60%+ 구간 편향은 **−0.145**로 현행 모델(−0.149)과 거의 동일했다 —
  운량 소스가 좋아도 다른 병목(당시엔 미상)이 있었거나, 이번 조사와 무관한 구조적 차이.

## 실사례 진단 — 2026-09-20, 09-22

둘 다 18z 당일예보(horizon_d=0). 일사 예보는 근접했는데(예: 09-20 13시 서부 예보 2.97
vs 실측 3.15) **운량 예보가 완전히 틀렸다**(같은 시각 서부 전운량 예보 0.53~0.99 vs
실측 0.0~0.2). 09-22 11~16시는 예측 이용률이 0.48~0.51 에 평평하게 눌려 실측
(0.66→0.88→0.71)을 전혀 못 따라갔다.

**레이어(L/M/H) 분해로 두 가지 다른 실패 유형을 확인**(예보 low/mid/high 원시값은
2026-08-04부터만 DB 존재 — 그 전 기간은 분해 불가):

- **"허수형"(09-20 서부)** — L·M 은 예보도 거의 0(진짜 맑음)인데 **H(고층운/권운) 혼자
  0.7~0.99**를 찍어 total_cloud 를 다 끌어올림. `REPORT_cloud_feature_audit.md` 가
  이미 밝힌 메커니즘 그대로(권운 과대반영).
- **"진짜형"(09-22 남부)** — **L(저층운) 자체가 0.79~0.94로 잘못 예보**됨. 고층운 가중을
  낮춰도 못 고친다 — NWP 모델이 그 시각 저층운을 진짜로 잘못 맞힌 경우.

→ **층별 재가중은 "허수형"만 고치고 "진짜형"은 못 고친다.** 두 유형이 날마다 섞여 있어
하나의 고정 공식(예: `L+0.7M+0.25H`)으로는 반만 해결된다 — §8 재현 실패의 이유와 일치.

## 서빙 시점 재보정 검증 — 월별 순환 홀드아웃(leave-one-month-out, 2025-12~2026-09, 10폴드)

단방향 홀드아웃·실측 구간 가르기의 함정(진행기록 §주의사항)을 피하려고 **매달 한 번씩
held-out** 하며 su(선형 OLS 대리모델, `su ~ 후보입력`)를 학습→평가했다. 지표 =
held-out 폴드의 실측 이용률 60%+ 구간 평균 (예측−실측).

| 후보 | 10폴드 평균 편향(60%+) | 비고 |
|---|---|---|
| 현행(raw `total_cloud`) | **−0.198** | 기준 |
| `midlow_cloud` 단독 | −0.160 | |
| `total_cloud`+`midlow_cloud` 선형결합(폴드마다 재적합) | **−0.156** | 연중 고르게 20%↓, 저위험 |
| L/M/H 물리가중(`L+0.7M+0.25H`, 2026-08~09 2개월만·참고용) | −0.158 | T+ML 대비 추가 이득 거의 없음 |
| L/M/H 자유가중 OLS(위와 동일 2개월) | −0.153 | 동상 |
| **`total_cloud` × `radiation` 교호작용(게이팅, 연속형)** | **−0.107** | **월별 편차 큼(아래)** |
| 하루단위 게이팅(일사 P60 절대임계값) | −0.116 | 위와 유사 |

### 게이팅의 월별 편차 (교호작용 후보)

| 월 | 편향 | 비고 |
|---|---|---|
| 2025-12 | −0.181 | 악화(기준 −0.078) |
| 2026-01 | −0.167 | 악화(기준 −0.092) |
| 2026-02 | −0.181 | 소폭 악화 |
| 2026-03~09 | **−0.03 ~ −0.19**, 5월은 **+0.04**(반전) | 대부분 크게 개선 |

**겨울(12~2월)에 오히려 악화되는 이유를 계절 정규화(그 달 중앙값으로 스케일 제거)로
고치려 했으나 실패** — 아카이브가 10개월뿐이라 12월은 held-out 시 학습셋에 다른 해
12월이 전혀 없다(기준점 자체가 없음). **코드 문제가 아니라 데이터 구조적 한계.**

⚠**5월의 +0.04 반전은 방향 주의**: 이 코드베이스 관례상 과대예측(+)이 과소예측(−)보다
위험한 방향(net_load 과소 = 발전 준비 부족)이다. 게이팅을 그대로 적용하면 일부 달에서
"안전한 과소예측"이 "위험한 과대예측"으로 바뀔 수 있다 — 배포 전 반드시 확인할 것.

## 결론 / 다음 세션이 이어갈 것

1. **게이팅(일사×운량 교호작용)이 가장 유망하다** — 4~9월(발전량이 크고 실무적으로
   중요한 계절)에서 편향을 반 가까이 줄인다. **12~2월은 검증 불가**(데이터 부족) —
   겨울엔 적용하지 않거나 별도 처리가 필요.
2. **다음 세션 후보 작업**:
   - 계절(월) 제한: 검증된 3~9월(또는 4~9월)에만 게이팅 적용, 10~2월은 현행 유지.
   - 게이팅 계수/임계값을 더 다듬기(지금은 단순 OLS 교호작용 1항 또는 P67 이분법 —
     더 정교한 continuous gate 여지 있음).
   - 5월 반전(+0.04) 같은 과대예측 방향 위험을 개별적으로 재확인.
   - 실제 서빙(`forecasting/serve_solarwind.py`)에 넣을지, `solar_scale.json` 처럼
     별도 후처리 설정파일로 둘지 설계 결정 — **아직 미정, 이번 세션에서 적용 안 함.**
   - 겨울 검증은 아카이브가 한 해 더 쌓인 뒤(2026-12~2027-02 확보 후) 재시도.
3. **재훈련(Colab) 관련 별도 메모**: D+1~D+3만 훈련하고 D+4/D+5는 D+3 가중치를 재사용하는
   방안이 사용자 제안으로 나왔음(경험적으로 차이가 작다는 판단) — 아직 미실행, 재훈련
   착수 시 반영 검토.
4. **old/new 병렬 서빙 인프라 계획은 중단됐다** — 재훈련보다 운량 입력 자체를 바로잡는
   게 먼저라는 판단(사용자 확정, 2026-09-27). 관련 설계는 실행하지 않았다.
