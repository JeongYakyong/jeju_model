> 서로 다른 물리량을 담고 있다.** `midlow_cloud` 는 상대적으로 멀쩡하다.
>
> 선행 문서 → `REPORT_solar_clearsky_underprediction.md` (원인이 예보 운량임까지 규명).

표본: `forecast_kimg` D+1~D+5 × `historical` 맞물림, **낮시간 09~16시**,
2026-02-10 ~ 2026-08-24 (D+1 기준 1,518행). 12z 전용.

## 1. 모델이 실제로 먹는 운량은 4개다

`models/solarwind_patchtst/metadata.pkl` 의 `future_features_solar` 실물:

```
solar_rad_west,  total_cloud_west,  midlow_cloud_west,  solar_damping_west,
solar_rad_south, total_cloud_south, midlow_cloud_south, solar_damping_south,
Hour_sin, Hour_cos
```

- 운량 = **`total_cloud` + `midlow_cloud`, west·south 2지점 = 4개**.
- **`low`/`mid`/`high` 원시값은 DB 에 있지만 모델에 안 들어간다** (2026-08-04 수집 추가분).
- `east` 는 태양광 입력이 아니다 (`SOLAR_STATIONS = west, south`).

## 2. 어디서 오는가 — 단일면/등압면과 결합식

| 컬럼 | 소스 | 종류 | 결합식 |
|---|---|---|---|
| `total_cloud_*` (서빙) | KIMG NE57 `tcld` (varn 37) | **단일면 진단장** | **없음 — API 원본 그대로** |
| `midlow_cloud_*` (서빙) | KIMG `lcld`+`mcld` | 단일면 | **`lcld + mcld·(1−lcld)`** (random overlap) |
| `low/mid/high_cloud_*` | KIMG `lcld`/`mcld`/`hcld` | 단일면 | 원본 그대로 (아카이브용) |
| `total_cloud_*` (KIMR) | R030 **등압면 CLDFRA 24레벨** | 등압면 | max-random 오버랩 |
| `midlow_cloud_*` (KIMR) | 같은 등압면 | 등압면 | `low + mid(1−low)`, low=max(≥800hPa) |
| `total_cloud_*` (실측) | KMA ASOS 전운량 | 관측 | 0~10 → ÷10 |
| `midlow_cloud_*` (실측) | ASOS 중하층운량 | 관측 | 0~10 → ÷10 |

**서빙에 들어가는 것은 전부 KIMG 단일면이다.** 등압면(KIMR)은 아카이브에만 있고
서빙·학습 어디에도 안 쓰인다.

결합식 검증 — 저장된 `midlow_cloud` 는 `lcld+mcld(1−lcld)` 와 **3지점 전부 MAE 0.000000,
일치율 100%**. `total_cloud` 는 층별 random-overlap 재계산과 MAE 0.010~0.014 로
**정확히 일치하지 않는다 = API 가 독립 진단한 원본이 맞다.**
물리 모순(`total < max(층별)`)은 0.0~0.1% 로 무시 가능.

## 2-1. `tcldc` 검토 — 쓰면 안 된다 (2026-08-25 API 실측)

KIMG 변수표에 `tcld`(Total Cloud Cover, "atmos col.")와 `tcldc`(**Convective** Cloud
Cover, "entire atmosphere considered as a single layer")가 나란히 있고, `lcld`/`mcld`/
`hcld` 는 `tcldc` 와 같은 레벨 표기를 쓴다.  "`tcld` 만 범주가 다른 것 아닌가" 를
API 원시 응답으로 확인했다 (base 2026082412, 2지점 × hf 1~48 = 96행 전량 수신).

**① 레벨 표기는 응답에 없다 — 다섯 변수 전부 `LEVEL = 0`.**

```
2026082412 2026082500       37        0  7.70000e-01  tcld(1)
2026082412 2026082500       61        0  2.98023e-08  tcldc(1)
2026082412 2026082500       34        0  7.70000e-01  lcld(1)
2026082412 2026082500       35        0  0.00000e+00  mcld(1)
2026082412 2026082500       36        0  9.00000e-02  hcld(1)
```

문서의 "atmos col." vs "entire atmosphere (considered as a single layer)" 는 GRIB2
level 표기 관례(코드표 4.5의 10번 / 200번)를 옮긴 것으로, 둘 다 **연직 기둥 전체**를
뜻한다.  층 구분은 레벨이 아니라 **변수 이름**이 담고 있고, 실제로 세 층은 분포가
확연히 다르다(`mcld` 는 85%가 0, `hcld` 는 평균 0.486).

**② `tcldc` 는 거의 항상 0 이다** (96행 실측):

| 변수 | 평균 | 중앙 | 최대 | =0 비율 |
|---|---|---|---|---|
| **`tcldc`** | **0.000625** | **0.000** | **0.050** | **97.9%** |
| `tcld` | 0.619 | 0.735 | 1.000 | 11% |
| `lcld` | 0.475 | 0.505 | 0.990 | 15% |
| `mcld` | 0.033 | 0.000 | 0.850 | 85% |
| `hcld` | 0.486 | 0.485 | 1.000 | 24% |

`tcldc` 는 **적운 대류 파라미터화 스킴이 만든 구름만** 담는다 — 전운량이 아니라
전운량의 부분집합이고, 0.1 을 넘는 경우가 한 번도 없었다.  이것을 total cloud 자리에
넣었다면 모델은 사실상 "항상 맑음"을 받았을 것이다.  **`tcld` 선택이 맞다.**

**③ `tcld` 는 층별의 기둥 결합이 맞다** — 다른 필드가 아니다.
6개월 DB: random-overlap3 대비 MAE 0.0099 / r 0.995.  신규 프로브 96행:
random 0.0315 / max-overlap 0.0186.  즉 `tcld ≈ lcld·mcld·hcld 의 오버랩 결합`이고,
§3~§5 의 진단(권운이 여름에 `tcld` 를 밀어올린다)은 **변수 선택 착오가 아니라
그 결합이 의도대로 작동한 결과**다.

**④ 다만 이 확인 과정에서 새로 잡힌 것 — 예보 상층운 자체가 과예보다.**
실측에는 상층운 관측이 없어 대리지표를 만들었다:
`실측 상층 대리 = (전운량 − 중하층운량) / (1 − 중하층운량)` (random overlap 역산).

| 월 | 예보 `hcld` (west) | 실측 상층 대리 | 차이 |
|---|---|---|---|
| 2026-02 | 0.320 | 0.237 | +0.084 |
| 2026-04 | 0.502 | 0.456 | +0.046 |
| 2026-06 | 0.701 | 0.546 | +0.154 |
| **2026-07** | **0.724** | **0.292** | **+0.432** |
| 2026-08 | 0.735 | 0.413 | +0.323 |
| **전체** | **0.527** | **0.354** | **+0.173 (+49%)** |

중하층은 +0.111(+37%), south 상층은 +0.054 로 west 가 특히 심하다.
⚠**대리지표의 한계**: ASOS 관측자가 얇은 권운을 낮게 세면 대리값이 낮게 나온다.
따라서 +49% 는 **모델 과예보량의 상한**이고, 일부는 관측 미탐지일 수 있다.
현재 데이터로는 둘을 완전히 분리할 수 없다.

## 9. 재학습 세션에 넘기는 것

우선순위 순:

1. **`total_cloud` 를 뺀 재학습을 기준선으로.** 가장 큰 편향원이고, 제거는 자유도를
   **줄이는** 방향이라 과적합 위험이 없다. 홀드아웃은 2026-06~08.
   대가는 겨울·봄 저층 overcast 판별력 — 그때는 `total` 이 실제로 저층을 대표했다(§3).
2. **`midlow_cloud` 는 유지.** 정보량 손실 −0.0~−6.1% 로 사실상 정합한다.
3. **층별 raw 6개 투입은 권하지 않는다** — 선형 R² 0.529→0.536, 사실상 무이득(§6).
4. **투과가중 지표는 후보로만.** §8 대로 계절 잔차가 남고 계수가 자유도다.
   쓰려면 학습·서빙 **양쪽에서** 같은 식으로 만들어야 하는데, ASOS 에는 층별 관측이
   없어 **학습 쪽을 만들 수 없다** → 실질적으로 "서빙에서만 total 자리에 끼워 넣는"
   입력 치환이 되고, 그건 검증 부담이 큰 선택이다.
5. **장지평(D+4~5)은 운량이 아니라 일사가 주범**(§5, radiation +0.132 > total +0.105).
   운량만 손봐서는 D+5 가 안 낫는다.

"학습은 ASOS 축, 서빙은 예보 축"이라는 근본 불일치를 없애는 유일한 구조적 해법이라

  여름 외삽이 안 된다.  `Year_sin` 이 최상위 피처로 뽑히는데 학습창에 여름이 없다.
- `lwdown` 은 광학 두께 대리로 물리적으로 타당하나 **표본이 얇아 과적합만 키웠다**.
- ★**재시도 조건**: `forecast_kimg` 층별·`lwdown` 이 **18개월 이상**(2027-08경) 쌓이면
  계절 외삽 없이 다시 시도할 수 있다.  그 전에는 무의미하다.

### 10-4. 그래서 남은 것 — 예보 품질이 천장이다

같은 OLS 에 입력만 교체(§ 선행 리포트 정정 참조):

| 입력 | MAE | 맑음 편향 |
|---|---|---|
| **전부 실측 (모델 성능 상한)** | **0.0764** | **−0.0282** |
| 전부 예보 (서빙 조건) | 0.1125 | −0.0704 |

**MAE 가 47% 벌어진다.**  모델·피처·후처리를 어떻게 만져도 이 격차 안에서만 움직인다.
맑음 편향 악화 −0.042 는 **일사 44% / 운량 56%** 로 거의 반반이고,
MAE 악화는 **일사가 86%** 를 낸다.

**결론: 현행 구성을 유지한다.  개선 지렛대는 모델이 아니라 예보 아카이브 축적이다.**

### 10-5. `lwdown`(하향 장파)은 광학 두께 신호가 아니다 — 기대와 반대

흐린 날 "운량은 맞는데 일사가 +49% 과대"(= 두께를 못 맞힌다)를 메울 후보로 검토했다.
`lwdown` 은 구름 밑면 온도·두께의 대리로 물리적으로 타당해 보였다.  **아니었다.**

예보 전운량 > 0.85 인 805행을 `lwdown` 4분위로 가르면:

| lwdown 구간 | lwdown | 실측 일사 | 예보/실측 |
|---|---|---|---|
| 하위 25% | 306 | 1.676 | 1.184 |
| 25~50 | 371 | 1.100 | 1.252 |
| 50~75 | 410 | 1.433 | 1.091 |
| **상위 25%** | 435 | **1.711** | **0.973** |

**`lwdown` 이 높을수록 실측 일사가 높다** — 두께 신호라면 반대여야 한다.
`lwdown` 은 대기 기온·습도에 지배되어(여름에 크다) 두께가 아니라 계절을 담는다.

일사 오차 증분 설명력(OLS R², D+1 낮 1,508행)이 확증한다:

| 입력 | R² |
|---|---|
| 현행 입력만 | 0.1146 |
| + **난수(대조군)** | 0.1147 |
| + `lwdown_west` | 0.1172 |
| + `temp`·`reh` | **0.1730** |
| + `lwdown` + `temp`·`reh` | 0.1782 |

`temp`·`reh` 가 훨씬 강하고 둘을 합쳐도 거의 안 는다 = **`lwdown` 의 고유 정보가 없다.**

### 10-6. 그런데 `temp`·`reh` 도 판정 불가 — 표본이 부족하다

피처 2개 추가 후보를 네 가지 검사로 재면 **순위가 매번 뒤집힌다**:

| 구성 | LOMO OLS | LOMO LGBM | 정방향 | 역방향 |
|---|---|---|---|---|
| A 현행 | 0.1076 | 0.1181 | **0.1170** | 0.1338 |
| B +`temp` | 0.1093 | 0.1143 | 0.1313 | **0.1246** |
| C +`reh` | **0.1067** | 0.1208 | 0.1230 | 0.1310 |
| E +`lwdown` | 0.1093 | **0.1102** | 0.1499 | 0.1361 |
| **Z 난수 2개 (대조군)** | 0.1078 | 0.1189 | 0.1191 | 0.1344 |

★**결정적인 것은 마지막 줄이다.**  의미 없는 난수 2개를 넣어도 현행 대비 0.1~1.8% 움직이는데,
**후보들의 이득도 전부 그 범위 안**이다.  `+lwdown` 은 LOMO LGBM 1위이면서 정방향 꼴찌,
`+temp` 는 역방향 1위이면서 정방향 꼴찌다 — **방향이 뒤집히는 것은 잡음을 맞추고 있다는 신호.**

→ **1,508행(D+1, 6.5개월)으로는 피처 2개의 효과를 난수와 구별할 수 없다.**
   `temp`·`reh`·`lwdown` 전부 판정 보류.  **결론은 다시 아카이브 축적이다.**

### 10-7. 남은 미해결 문제 (다음 기회에)

1. **흐린 날 일사 +49% 과대의 원인이 미상이다.**  운량은 맞고(−0.012), 장파는 설명 못 하고,
   기온·습도도 확실하지 않다.
2. **KIMG API 에 진짜 광학 두께 변수가 있는지 미확인** — 구름 수분량(`qc`/`qi`)·
   광학깊이(`taucld`) 계열.  프로브해 본 적 없다.  있다면 1번의 정답일 수 있다.
3. **재학습 원인 분리** — Year 와 split 을 함께 바꿔 무엇이 나쁘게 했는지 모른다.
   다시 한다면 `train ≤2026-01` / `val 2026-02~05` 유지 + **Year 만** 추가.

### 10-8. 최종 방침 (사용자 확정 2026-08-25)

**현행 구성을 그대로 두고 `solar_scale` 후처리로 버틴다.**
맑은날 과소예측은 **안전 방향 오차**(net_load 과대 = 발전 준비 여유)이고,
위험 방향인 흐린날 과대는 `solar_scale` 이 이미 누르고 있다.
개선 지렛대는 모델이 아니라 **예보 아카이브 축적**이며, 재시도 조건은
`forecast_kimg` 층별·`lwdown` **18개월(2027-08경)** 이다.
